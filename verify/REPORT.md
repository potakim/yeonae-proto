## 발견 사항과 조치

### 1. [수정함] 진태양시를 끄면 과거 표준시·서머타임까지 무시됨 — 래퍼 버그
라이브러리는 `trueSolarTime` 옵션을 **빼면** 입력 시각을 무조건 현재 KST(UTC+9)로 간주한다.
그래서 프로토타입에서 '진태양시 보정'을 끄면 아래 출생자의 시각이 30~60분 틀어졌다.

- 1954-03-21 ~ 1961-08-09 출생 (당시 표준시 UTC+8:30) → 30분
- 서머타임 기간 출생 (1948~51, 1955~60, **1987~88**) → 60분

| 예 | 수정 전 | 수정 후 |
|---|---|---|
| 1988-07-15 09:40 (서머타임 → 실제 KST 08:40) | 계사시 | 임진시 |
| 1958-01-10 06:50 (UTC+8:30 → KST 07:20) | 계묘시 | 갑진시 |

이 시기에 태어난 사람이 진태양시를 끄면, 서머타임 기간은 약 절반, UTC+8:30 기간은 약 1/4의 시주가 바뀔 수 있었다. 절입일 출생이면 월주도 바뀐다.
1987~88년생은 주 타깃 연령대라 영향이 크다.

**조치:** 진태양시를 꺼도 `{ longitude: 135, applyEquationOfTime: false, applyHistoricalDst: true }`로 넘겨서, 벽시계를 실제 KST로 환산하는 단계는 항상 거치고 경도·균시차 보정만 끄도록 변경. 회귀 테스트 3건 추가.

### 2. [주의] 2050년 이후 음력은 한국 기준이 아님
라이브러리 음력표는 1391~2049년은 KASI, 2050~2100년은 중국식 천문계산(6tail)이다.
2050년 음력 1월이 KASI 기준(30일)과 달리 29일로 되어 있어 2050년 2월 이후 날짜가 하루씩 밀린다.
출생일 입력에는 해당이 없고, 2050년 이후 음력 날짜를 보여줄 일(장기 운세 등)이 생기면 그때 별도 처리하면 된다.

### 3. [관법 결정 필요] 라이브러리 오류는 아니지만 팀이 정할 것
- **진태양시를 켜면 일주도 진태양시 기준으로 바뀜.** 서울 출생 00:00~00:32 KST는 전날 일주가 된다. 일주는 KST 자정 기준으로 두는 학파도 있다.
- **대운수 반올림**: `round(일수 ÷ 3)`, 최소 1. 나머지 1일은 버리고 2일은 올리는 등 학파마다 다르다.
- **서머타임 종료일에 두 번 있었던 1시간** (예: 1988-10-09 02:00~02:59): 라이브러리는 서머타임 쪽(첫 번째)으로 해석한다. 이 경우만 사용자에게 물어보는 방법도 있다.
- **1908년 4월 이전 출생**: 라이브러리는 +9:00으로 계산한다(IANA는 지방평균시 +8:27:52). 실사용 영향 없음.

### 4. 절입 시각 정밀도 참고
- 라이브러리 절입표는 분 단위다. 1970년 이후로는 KASI 방식(반올림 분)과 거의 일치한다.
- 1900~1960년대에는 DE421 기준과 ±1분 차이가 연대당 15~83개(120개 중) 있다. 이 시기는 천문 기준끼리도(DE421 vs astronomy-engine) 최대 80초 차이가 나서 어느 쪽이 KASI 역서와 같은지는 KASI 과거 자료 확보 후 확정할 수 있다.
- 출생 시각이 절입 '직후 1분 이내'일 확률은 약 0.002%로, 실사용 위험은 매우 낮다.

## 한국 기준 2차 점검 (2026-11-11)

"대한민국에서 쓰는 만세력"으로서 문제가 되는 지점을 따로 확인했다.

### 계산 자체는 한국 기준을 따른다 (문제 없음)
- **음력**: 한국·중국 음력이 다른 날(1900~2049년 1,948일)에서 모두 한국 쪽을 따른다.
  예: 1997-02-07은 중국에선 음력 1/1(설날), 한국에선 12/30 → 라이브러리는 12/30.
- **서머타임·표준시**: 한국 역서 전재 자료의 1948년(6/1~9/13), 1960년(5/1~9/18) 서머타임 기간과 일치.
  1908~11, 1954~61년 UTC+8:30도 반영.
- **과거 역서 절입 시각**(2차 자료, `verify/data/kasi_historical_secondary.json`):
  1988년 24개 중 22개 일치(2개 1분 차이). 1948·1960년은 역서 값이 대부분 라이브러리보다 1분 늦다.
  현대 천문계산(DE421)과는 더 멀어서(24개 중 3개 일치) 당시 역서의 계산 정밀도 차이로 보인다. 영향은 절입 1분 이내 출생뿐.
- **윤달 오입력**: 없는 윤달을 넣으면 "2024년에는 윤3월이 존재하지 않습니다"처럼 한국어 오류를 낸다.

### 한국 관행과 다르게 나올 수 있는 부분 (결정 필요)

**1. 시주 시간 기준 — 가장 큰 차이** (`node verify/korea-conventions.mjs`)
국내 만세력은 크게 세 가지 시간 기준을 쓴다.

| 기준 | 자시 구간(서울, KST) | 쓰는 곳 |
|---|---|---|
| 진태양시 (경도+균시차) | 날짜마다 다름, 23:16~23:46 사이에 시작 | 앱 기본값. 학술적으로 권장되는 편 |
| 30분 보정 (동경 127.5°) | 23:30~01:29 | 국내 만세력·사주 앱에서 흔함 |
| 정시 (동경 135°) | 23:00~00:59 | 라이브러리 옵션 미지정 기본값, 앱에서 진태양시를 껐을 때 |

서울 출생 1975~2005년 무작위 50,000건에서 기준끼리 원국이 달라지는 비율:

| 비교 | 시주 | 일주 |
|---|---|---|
| 진태양시 vs 30분 보정 | 6.7% | 0.5% |
| 진태양시 vs 정시 | 29.2% | 2.2% |
| 30분 보정 vs 정시 | 26.9% | 2.0% |

→ 사용자가 다른 앱과 비교하면 최대 약 30%가 "시주가 다르다"고 느낄 수 있다.
현재 앱에서 진태양시를 끄면 '정시(135°)'가 되는데, 한국에서 '보정 안 함'은 오히려 30분 보정을 기대하는 경우가 많다.
**권장:** 시간 기준을 `진태양시(기본) / 30분 보정 / 정시` 3가지로 노출하고, 결과에 어떤 기준인지 표시.

**2. 자시(23시대) 처리 — 기본값이 국내 주류 학설과 다를 수 있음**
라이브러리 기본 `midnight`는 23시대에 **일주도 당일, 시주 천간도 당일 일간 기준**이다.
(예: 2024-03-10 23:30 → 계유일 **임자시**. 같은 날 00:30도 임자시라 하루에 임자시가 두 번 생긴다)
국내에서 주로 보는 방식은 둘이다.
- 자시부터 다음날 (`jasi`): 갑술일 갑자시
- 야자시: 일주는 당일, 시주는 다음날 기준 (`splitJasi`): 계유일 갑자시

출생의 약 4%(23시대)가 해당한다. **권장:** 기본값을 `jasi` 또는 `splitJasi` 중 하나로 팀이 정하고, 설정에서 바꿀 수 있게 유지.

**3. 표기 관련**
- 띠: 사주(궁합의 '띠' 항목 포함)는 입춘 기준인데, 일반인은 설날 기준으로 띠를 아는 경우가 많다.
  1~2월 초 출생자에게는 "사주에서는 입춘 기준이라 OO띠로 봐요" 안내가 필요하다.
- 대운 나이: 앱은 실제 날짜로 현재 대운을 고르고 '만 나이'로 표시한다. 국내 만세력 중에는 대운수를 세는 나이로 읽는 곳도 있어 숫자가 1살 다르게 보일 수 있다. 표시 기준을 화면에 명시하면 된다.

## 결정 반영 (2026-11-11)

위 '결정 필요' 항목을 아래처럼 확정해 코드에 반영했다 (README '한국 기준 기본값').

- 시주 시간 기준: 기본 **한국 표준 보정(127.5°)**, 선택 진태양시·보정 없음. 결과에 적용 기준 칩과 다른 기준의 결과를 함께 표시
- 자시: 기본 **자시부터 다음날**, 선택 야자시 적용. 엔진 `midnight`는 입력에서 제외
- 연주 입춘 유지, 설날 기준 띠와 다르면 안내 (원국 화면·궁합 '띠' 항목)
- 대운 표기: `N대운 · 만 X세 Y개월(YYYY년 M월)부터`
- 오늘 운세의 일진도 같은 기준 (한국 표준 보정이면 23:30부터 다음날)
- 운세·궁합 캐시 키에 원국 스키마 버전(v3) 포함

## 재실행 방법

```bash
pip install skyfield skyfield-data     # NASA JPL DE421 천체력 포함
python3 verify/ref_solar_terms.py      # 기준 절입표 생성 → verify/data/ref_solar_terms_de421.json
npm run verify                         # 전 항목 대조 → verify/data/report.json
npm test                               # 앱 단위 테스트 (회귀 테스트 포함)
node verify/korea-conventions.mjs      # 한국 시간 관행별 원국 차이 측정
```

라이브러리 버전을 올릴 때는 이 검증을 다시 돌려 결과가 같거나 나아지는지 확인한다.

## 사용한 기준

- NASA JPL DE421 천체력 + Skyfield 1.55: 태양 겉보기 지심 황경(광행차·장동 포함)이 15° 배수가 되는 순간
- 한국천문연구원 천문우주지식정보 24절기 표 (2025·2028), KASI 2026 천문력 PDF
- korean-lunar-calendar (KASI 음양력 데이터 기반, 1000~2050)
- lunar-javascript 1.x (중국 음력, 한국/중국 차이 확인용)
- astronomy-engine 2.x (VSOP87, 절입 기준 교차확인·균시차)
- Node 내장 IANA tz database (Asia/Seoul)
